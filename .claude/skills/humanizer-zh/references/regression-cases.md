# 歷史失敗與處置

本檔收納曾造成實際品質問題的情況。遇到相似訊號時讀取，不要把案例文字抄進文章。

## 高風險失敗

| 失敗 | 常見原因 | 必要處置 |
|---|---|---|
| 文章漏掉逐字稿的重要段落 | 只修文章已有內容，只做文章→逐字稿單向檢查 | 逐字稿→文章方向也要走一遍，重要內容補回 |
| 成品出現逐字稿查無的整段 | `/yt` 長字幕會幻覺出平行下半段與捏造引述 | grep 抓不到，要逐句回字幕；查無就整段刪 |
| billion 被寫成「億」 | 英文量級未換算 | million＝百萬、billion＝十億、trillion＝兆；少乘十倍即致命 |
| 主持人與來賓說反 | 依段落位置或語氣猜 speaker | 先做 speaker map，再逐引述核對上下輪對話 |
| 多人句子被縫成單一引述 | 為了流暢合併 | 拆回各自講者；無法定位就降級為「節目中提到」不指名 |
| 數字看似合理但方向錯 | 只核數值，未核單位與比較詞 | 同時核對數值、單位、增加至／增加了、上下限與時間 |
| 專名被 ASR 誤辨 | 只靠字面或搜尋第一筆 | 逐字稿上下文加可靠來源雙重核實；重建不出就標 `ASR 存疑` |
| 查到的詞不是講者要說的詞 | 把搜尋命中當證據（IMEC／in-rack） | 搜尋只證明詞存在；近似拼字要用語境驗證 |
| 中文通順但新增因果 | 用連接詞替來源補邏輯 | 刪除未被逐字稿支持的「因此、為了、意味著」 |
| 日韓來源整段不翻譯 | 提示與檢查只綁英文 | 假名／諺文殘留視為硬失敗，全部譯成繁中 |
| Gate 通過但文章仍難讀 | 把機械檢查當成編輯審查 | 保留獨立的冷讀與 fresh reviewer（必須是沒參與改稿的新 agent）|

## 可見的文氣退化

- 「不是……而是……」「沒有 X 卻 Y」「不只 X 也 Y」密集出現時，做全文同族句型掃描，不只替換被點名的一句。
- 「話鋒一轉、把問題拉回、他的重點是、開門見山」通常是編輯旁白。刪除後直接寫內容。
- 同段重複常藏在「旁白摘要 → 引述 → 再摘要」。只留不可替代的那一層。混血串接（複述句焊在有真數字的句子裡）要逐句判，不要整段一起放行。
- 查證侵入正文的最短反例：「這是 Baker 轉述的市場假設，不是公司財測」「並非已經落地的確定預測」「不代表每個專案都有相同結果」「只能證明／不能證明」「兩者是不同指標」。刪句測試不影響事實與邏輯就刪。不要動講者原話中的真正限制。
- 財務、科技、投資影片最容易被改成審計報告：比喻、反問與判斷消失，只剩核對表。整段重建，用直接引述讓講者自己推進論證，別做刪句美容。
- 該引述卻轉述的最短反例：把「他說這根本是在燒錢」改寫成「他對投資報酬持保留態度」。還原成原話。
- 第一輪 ASR 草稿只是暫定文本；人名、公司、產品、數字、引述與歸屬都要重查。
- 「幹預」在 intervention／interference 語境統一為「干預」。

## 來源與發布邊界

- 字幕遇到 `IpBlocked`、HTTP 429 或 `TranscriptsDisabled` 時，及早改用既有本機逐字稿或經授權的 Whisper 路徑，不做密集重試。
- 本機 `_yt_` 路徑仍是完整 production workflow，除非使用者明確收斂範圍。
- 現有 HackMD 筆記需要修正時原位更新，不建立重複筆記。
- 缺逐字稿、audit 或 zero-hard-failure 證據時，不得宣稱完成發布。
