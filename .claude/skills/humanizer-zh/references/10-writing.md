# 寫作：脈絡重構與引述取捨

## 脈絡重構（`_yt_` 訪談專用，排在覆蓋對帳之前）

**為什麼需要這一階段：** humanizer 被定義成「只編輯不改寫」，本身不重組結構；`/yt` 產出的草稿又是照逐字稿的時間順序寫的。整條 pipeline 原本沒有任何一步負責決定文章骨架，於是骨架就等於逐字稿的骨架：講者繞回來講第三次的論點，文章就跟著寫第三次，讀者拿到的是一份通順版逐字稿。這一階段補的就是這個缺口。使用者的原話：「agent 看完原稿以後抓出脈絡與章節，再根據段落去適度的引用原話，讓讀者獲得訪談節目裡的 idea，且脈絡也保留。」

**與「只編輯不改寫」的分工（兩者不衝突，管的是不同層）：** 「只編輯不改寫」管的是**內容層**：不添料、不注入觀點、不刪講者細節、不替講者發明句子。它從來沒有保證「章節順序＝對話順序」。重排章節、把同一件事的四次發言合併成一節，動的是**排列**，一句話都沒有新增或發明，屬於編輯權限之內。反過來說，這一階段一旦開始改寫講者的意思、補講者沒說的推論，就是越權，回到內容層的禁令。

**輸入是逐字稿本身，不是 `/yt` 草稿。** 讀草稿只會沿用草稿的骨架，等於白做。
**產出只有大綱，不產出文章。** 大綱寫進 scratchpad 或 `_audit.md` 的暫存段落，正式改稿在後面的步驟做。

作法四步：

1. **切論點**：通讀逐字稿，切成論點清單（一個論點＝講者一個可獨立轉述的主張、例子、數據或立場揭露）。這份清單就是下一步論點認領表的左欄，兩者共用同一份切法。
2. **合併重複**：Podcast 會繞圈，同一件事講者常在不同時點講三四次。把講同一件事的論點**合併成一條**，並記下**他哪一次講得最強**：最具體、有數字、有比喻、有第一人稱立場的那一次。那一次才是留原話的地方，其餘各次留給模式 36 降級成敘述。
3. **依論證關係排章節，不依對話時間順序**：先問「這篇的論證怎麼走」（前提 → 機制 → 反方 → 結論；或現象 → 成因 → 影響 → 部位），再把合併後的論點掛到章節上。逐字稿第 40 分鐘的話可以排進第一節，這是編輯，不是竄改。
4. **每節先寫兩行再動筆**：一行寫這節要傳達的 idea 一句話，一行寫用哪一到兩段原話撐它（標出字幕位置）。**寫不出那句 idea 的節，就是不該獨立成節**，併進別節或刪掉。

**與「講者聲音的機械下限」的關係：** 章節重排完之後才檢查下限（至少半數 `##` 章節要有代表性直接引述）。合併重複讓每一節都拿到「講得最強的那一次」，通常會讓下限更容易達成；若某節重排後湊不出代表性原話，先回頭問這節是不是不該獨立成節，不要拿平淡原話湊數。

**交付：** 大綱（章節 → idea 一句話 → 撐它的原話）與論點認領表一起附上，見〈交付清單〉第 7 項。

### 36. 引述的功能門檻（這段原話有沒有帶來轉述做不到的東西）

**問題：** 講者在 Podcast 裡會把同一句話講兩三次。第一次是論證的核心，第二次只是繞回來再講一遍。兩次都保留原話，文章就變成逐字稿；把原話刪光改成第三人稱轉述，讀者就失去講者的聲音。使用者連續退掉的兩版，一版犯前者，一版犯後者。

**判準（每一段引述都問一次）：這段原話有沒有帶來轉述做不到的東西？** 四種算有：**具體數字、比喻、語氣強度、第一人稱的立場揭露**。
- **有 → 留原話**，一個字不動。
- **沒有（只是把前面講過的論點再講一次）→ 降級成敘述句**：拿掉引號，把那句話的關鍵措辭織進敘述裡。**不要整段刪掉**（措辭是資產），也**不要改寫成看不出原話的第三人稱摘要**。

**使用者親自示範的正例（重複出現的「一個 token 就是一個 token」）：**
> 第一次出現，留原話：「一個 token 就是一個 token。」
> 第二次出現，降級成節尾敘述：`而這對基礎設施的需求是好事，理由還是那一句：一個 token 就是一個 token，做出來要花掉一樣的 flops、瓦數、空間和散熱。`
> 既沒有重複，也沒有丟失講者的措辭。

**三種處理，只有一種對（前兩種都被退過件）：**
- ❌ **刪掉原話改成第三人稱轉述**（「他強調 token 的成本結構不會改變」）：講者的聲音沒了，這是被退件的乾摘要版。
- ❌ **兩次都保留原話**：同一句金句在文章裡出現兩遍，讀起來像逐字稿，這是被退件的另一版。
- ✅ **第一次留原話、第二次降級成敘述**：措辭還在，重複沒了。

**與「既有引述改成轉述是受限操作」的分工（不要當成互相打架）：** 那條規則管的是**單一引述在原地被改成轉述**，門檻是回字幕核對＋`_audit.md` 四欄（原引述、轉述結果、字幕依據、改動理由）。本模式管的是**同一論點被引述兩次以上時該留哪一次**：留講得最強的那一次，其餘各次降級。降級也是一種「引述改轉述」，四欄記錄照樣要寫，改動理由填「模式 36：同一論點第二次出現，無功能增量」。**第一次出現（或講得最強的那一次）永遠不降級。**

**與「講者聲音的機械下限」的分工：** 降級只處理重複，不得把成品降到下限以下（至少半數 `##` 章節要有代表性直接引述）。如果降級後某節沒有原話撐了，代表你降錯了那一次，回頭改留那一節的原話。

**與模式 33 的分工：** 33 管的是「引述前後又把同一件事說一次」（同一處的重複）；36 管的是「同一論點在文章不同段落被引述兩次」（跨段落的重複）。

### 37. 敘述與引述的分工（串接句不做加值分析）

**分工一句話：敘述負責邏輯連接，引述負責畫面與強度。** 串接句的工作是把讀者從上一個論點帶到下一個論點：交代說話人、在回應什麼問題、對照什麼背景、時間點。畫面、比喻、情緒、力度全部交給引述自己給。

**串接句不做加值分析：** 引述裡已經讓讀者自己算得出來的東西，不要在串接句再算一次。使用者親自砍掉的實例：
> 引述：「原本每 GPU 小時兩塊多，七個月後要付四塊。」
> ❌ 後面補一句串接：`以起算點不同，這是六、七個月漲了 50% 到 60%。`
> ✅ 砍掉那一句。兩塊多到四塊，讀者自己會算；替他算一次只是把同一件事講兩遍。

**判別法：** 串接句寫完問一句「這句的內容，是不是從緊接的引述推得出來的？」推得出來就砍。留下來的必須是引述以外的資訊。

**與模式 33 的分工：** 33 抓的是串接句把引述的內容**先講一遍或再解說一遍**；37 抓的是串接句把引述的內容**再算一遍**（換算、百分比、加總、推論）。兩者同源，第 13 步 b 一起掃。
