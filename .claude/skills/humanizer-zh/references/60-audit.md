# 交付清單與覆蓋對帳

## 交付清單（證據型，取代自評分數）

**不做自評分數**——自己給自己打分沒有鑑別力，錯得離譜的稿子照樣能自評高分。改為交付時**必附**以下證據，讓使用者一眼能驗證工作確實做了。

**證據必須落檔，不准只寫在對話裡**：把完整交付清單（下列七項）寫入與文章同名的 `_audit.md` 檔（例：`2026-07-11_yt_XXX_humanized.md` → `2026-07-11_yt_XXX_audit.md`）。`upload_hackmd.py` 會在上傳前機械檢查：final_gate [硬性] 未清零、或 `_audit.md` 不存在，一律**拒絕上傳，無 bypass**。對話裡的清單會消失，檔案不會——沒有清單＝沒查。

1. **修改清單**：每處實質修改一條，格式「模式編號｜改寫前要點 → 改寫後要點」。純標點、格式類的修整可合併成一條總述。
2. **專有名詞核對表**（同時要落成機器可讀的 `<成品去後綴>_glossary.json`，處理流程第 12.5 步；`final_gate.py` 拿它當專名白名單，沒有它，ASR 還原得越正確、「英文專名字幕查無」就叫得越大聲）：全文的人名、公司名、產品名、學術概念逐一列出，每項標注核對結果：✓ 與字幕一致／✓ 網路查證屬實／⚠ 未能查證（保留原樣）。
3. **數字對帳結果**：同段落相關數字的量級、單位、方向對帳。沒問題就寫「無矛盾」，有修正就列出每筆「原文 → 修正後＋依據」。
4. **歸屬核對結果（僅多人 `_yt_`）**：每筆歸屬修正附字幕換手訊號為證（例：「『Simon 有補充嗎』→ 前段改歸 Beibin」）；核對過但無訊號的段落標「歸屬無字幕訊號，保留原判斷」。單人訪談寫「單人訪談，不適用」即可。
5. **流暢度朗讀證據**（處理流程第 13 步 a 的產出）：重譯清單（哪些句子因「中文不會這樣說」重譯）＋確認通順的代表句。全文本來就通順也要寫「逐句朗讀完畢，無需重譯」，不能省略。
6. **讀者冷讀與重複掃描結果**（處理流程第 13 步 b 的產出）：列出刪除的內容預告、報幕、引述前後複述，以及重要的引述／轉述取捨。每一筆「既有引述→轉述」固定列四欄：`原引述｜轉述結果｜字幕依據｜改動理由`；沒有轉述也要明寫「本篇無引述轉述」。一句都沒砍則寫「冷讀與逐對掃描完畢，無可刪重複」，不能省略。
7. **論點認領表＋章節大綱**（處理流程第 2.5、3 步的產出，有字幕時必附）：先附脈絡重構的大綱（章節 → 這節的 idea 一句話 → 撐它的原話），再附字幕論點清單，逐條標「**由哪一節承載**」＋「已承載／補回／捨棄」。被兩節認領過的論點要寫明擇一結果（留哪一節、另一節怎麼處理）。全部已承載也要附完整清單，不能只寫「無遺漏」帶過——沒有清單就無法區分「查過沒漏」與「沒查」。

缺任何一樣，工作不算完成。寧可清單寫「本篇無專有名詞」「無相關數字」「單人訪談，不適用」，也不要省略整個項目。

**修改清單的長度不是品質指標。** 一篇本來就乾淨的文章可以只改三處，清單短不是失職；為了讓清單好看而去動說不出依據的句子，才是失職（見「編輯權限結構」：說不出依據的句子，一個字都不要動）。
