# Humanizer-zh

**這個技能保證三件事：正確、完整、重新編排。**

**2026-09-21 政策反轉，讀舊版規則的人先看這一段。** 舊版的預設是「一律直接引述，編輯者少說話」，理由是引述不會捏造。代價是成品變成一份加了小標的翻譯稿，而體裁在這一關就定死了：下游拿到 0.90 引述佔比的稿子，怎麼潤都潤不成說明文（實測同一篇下游只把佔比從 0.902 壓到 0.834）。使用者因此說成品「幾乎無法用」。

所以**文筆與編排收回來自己做，不再外包**。現在的成品標準是：一篇按論證主線重新編排、去掉冗贅、以第三人稱敘述為主的說明文。

為什麼這一關做得到而下游做不到：**只有這裡拿得到逐字稿。** 下游模型看不到原文，它的「去冗贅」是在沒有 ground truth 的情況下猜的，刪掉什麼無法回頭驗證；它必須要求上游把命題、限定、歸屬、例子功能全部預先標成結構化欄位餵給它。那些標記對我們是多餘的，**寫作員手上就是原料本身**。

**因此明令禁止的三件事**：為了湊字數補水、為了佔比數字回頭重寫整篇、把「短」當成目標。短是重新編排與去冗贅的**結果**，不是規格；為了短而切碎句子，只會得到一份順序仍是流水帳的碎片稿。

## 規則的位階：哪些不准動，哪些是判斷

這份技能裡的規則分兩種，混為一談會把文章寫死。

**第一種：正確性規則，硬的，沒有裁量空間。** 歸屬、數字、限定、捏造、譯意、覆蓋、認知地位、錨點契約、命題清單。這些錯了就是錯了，寫得多好看都沒用，而且下游與讀者都查不出來，只有這一關查得出來。`final_gate.py` 與 `check_claims.py` 守的就是這一類。

**第二種：手藝規則，軟的，是預設值不是戒律。** 改寫層、去冗贅層、編排層、小標層裡的每一條判準、清單與優先序，都是「多數時候這樣做比較好」，不是「必須這樣做」。**寫作員與盲審員都可以偏離，條件只有一個：在 audit 寫一行為什麼。** 不必請示，不必道歉。

為什麼要這樣分：手藝規則寫死之後，模型會為了滿足規則而扭曲句子，得到的是一篇符合規格但難看的文章。**規則存在是為了讓不確定的人有依據，不是為了取代判斷。** 如果某條規則讓這一段變難看，那條規則在這一段就是錯的。

唯一不因「比較好看」而讓步的，是第一種。

## 權威與原則

- 逐字稿是內容、語意、說話人、數字與覆蓋的 ground truth。外部資料只用來核實專名，不得無解釋地推翻清楚的逐字稿。
- 本檔是流程與發布契約的唯一權威。參考檔依需要載入，不預先讀完：
  - [references/user-style.md](references/user-style.md)：SLK 的排版與格式偏好，**所有 `_yt_` 成品必讀**。
  - [references/rewrite-sample.md](references/rewrite-sample.md)：**新政策的文體範本，關 1 寫作前必讀。** 同一篇的兩個版本並排，左邊是技能產出、右邊是使用者認可的，正確性相同、差的全是手藝。七組對照：導言不要摘要全篇、一段一個意思、敘述先鋪原話收尾、小標從故事裡面看、場景比概述好、問句轉場、認知地位獨立成段。
  - [references/golden-sample.md](references/golden-sample.md)：**舊政策的範本（引述佔比 63%），體裁已作廢，不要讀。**
  - [references/regression-cases.md](references/regression-cases.md)：歸屬、數字、串接的實際翻車案例，高風險時讀。
  - [references/yt-triage-map.md](references/yt-triage-map.md)：輸入是 `type: yt_triage` 地圖版時讀。
  - [references/ai-writing-patterns.md](references/ai-writing-patterns.md)：**關 1 寫作前掃一遍，關 2 禁止拿它做掃描式修改**。文筆收回自己做之後它重新生效，但走的是源頭預防：寫的時候不要寫出來，比事後見詞就改安全得多（見 `_fb_` 路徑的慘痛紀錄：整批掃描式改寫造成矯枉過正）。
  - [references/self-authored-voice.md](references/self-authored-voice.md)：`_fb_` 專用。
- `scripts/final_gate.py` 是機械門檻，通過不代表正確，不能取代逐字稿核對與盲審。
- 保留原稿不動。寫作關輸出帶錨點的 `_draft.md`，交付檔 `_humanized.md` 由腳本剝錨點產生，不手寫。
- `_yt_` 交來的**不是文章**：選材、段落順序、小標、串接由 humanizer 決定，把訪談重新組織成有脈絡的稿子；但不加入編輯者第一人稱、心得或新論點。**動工前先讀 frontmatter 的 `type:`**（見〈輸入路由〉），同一目錄混著兩台機器的產出，不可假設全批同型。
- **紅線是結構性銜接 vs 內容性補充。** 結構性銜接只重組已有資訊、不宣稱新事實，可以寫：把讀者帶進下一段、指出這段在回應什麼、點出兩件事的關係、標示話題移動。新增逐字稿沒有的事實、數字、因果、立場或評價就是超譯，禁止。
- **自補的每一句都要通過一個檢查**：這句話我能不能指出它由逐字稿哪幾行直接推出？不能就刪。這不是自由心證，錨點契約要求你真的把行號寫上去。
- 逐字稿查無的整段一律刪除。
- 最終中文不使用 em dash `—`，零容忍，交付前全文搜尋清除。
- 正確性優先於一切。無法確認時保守措辭，不猜。
- 不修改 watcher、launchd、processed state、正式輸出路徑或憑證，除非使用者明確授權。

## 底稿辨識閘門（動筆前必過）

**不要一打開 `_yt_` 檔就開始潤稿。** 先只讀 frontmatter，再盤點同目錄同 base 產物；每個檔案單獨判型，不得依檔名、日期或同批其他檔案猜。

| 眼前的檔案 | 它是什麼 | 哪一層才是內容依據 |
|---|---|---|
| `type: yt_triage` 的 `_分流稿.md` | 給人選片的機器翻譯閱讀稿，**不是底稿** | `_lines.txt` 是 ground truth；`_map.json` 只是索引 |
| `type: yt_transcript_zh` | 中文全文順稿，是暫存翻譯與覆蓋骨架，不是成文 | `_transcript.txt` 決定語意、歸屬、數字與取捨 |
| `type: yt_article` | 舊版 `/yt` 已寫成的真正草稿 | 草稿結構受保護，但事實仍以 `_transcript.txt` 為準 |

固定 intake 順序：

1. 讀 frontmatter 的 `type`、`youtube_url`、`video_title`、`channel`、`map`、`transcript_lines`。
2. 盤點同 base 的原始檔、`_transcript.txt`、`_map.json`、`_lines.txt`、`_meta.txt`；記下缺什麼。
3. **`_meta.txt` 缺席時，root 先用 yt-dlp 補**（標題／description／章節時間碼），否則講者拼寫契約沒有合法來源、機械關必掛：
   ```bash
   yt-dlp --skip-download --no-warnings \
     --print "video_title: %(title)s" --print "channel: %(channel)s" \
     --print "upload_date: %(upload_date)s" --print "youtube_url: %(webpage_url)s" \
     --print "duration_seconds: %(duration)s" "<url>" > <base>_meta.txt
   { echo; echo "--- description ---"; \
     yt-dlp --skip-download --no-warnings --print "%(description)s" "<url>"; } >> <base>_meta.txt
   ```
4. `yt_triage` 必須先跑 `scripts/read_triage.py <三件組任一檔>`，照它列出的 base 與成品檔名走。
5. 通讀完整 ground truth 後才能寫；map 的 `segments`、`gist`、`claims_confirmed` 都不能代替通讀。

frontmatter 缺 `type:` 或與同目錄產物矛盾時停止寫作，向使用者說明缺什麼。**不得把分流稿當中文草稿、把順稿當文章，也不得在缺件時靠檔名補猜。**

## 行號錨點契約

**寫作關交出的每一段都要掛逐字稿行號。** 這是整條流程能省下人肉通讀的原因：漏段與斷尾從此靠腳本偵測，稽核員只看被標出來的點。

格式：緊接在該段之後，方括號包起來。

```
編輯者敘述一段，交代這題怎麼來的。[L200-211]

「講者的原話，一整則。」[L212-218]

「短一點的原話。」[L219]
```

規則：

- **每一段都要有自己的錨點**，錨點指向它實際依據的行。改寫成第三人稱之後這條更重要，不是更不重要：引號沒了，只剩行號能證明這句不是你寫的。
- **重排後一段可以掛多個不連續錨點**：`[L200-211][L455-460][L730-738]` 代表這段合併了講者在三個位置講的同一件事。腳本逐個計算，合併不會被誤判成漏段。
- **命題編號寫在錨點裡**：`[L81-84 #7]` 表示這段認領 plan (c) 的第 7 條命題。`check_claims.py` 用它確認沒有任何一條命題在重排中蒸發。一段涵蓋多條寫 `[L81-84 #7,#8]`。
- **單一錨點不得涵蓋超過 30 行**。用一個 `[L1-642]` 蓋全篇等於沒認領，`audit_worklist.py` 會判不可信並退件。
- 錨點是工作痕跡，不進交付檔。**`strip_anchors.py` 負責剝除，不要手動刪**。
- 小標、frontmatter、頁尾聲明不需要錨點。
- 刻意不寫的區段（廣告、寒暄、離題）不掛錨點，改在 `_plan.md` 與 audit 第 3 節列出理由；腳本會把它們報成未認領區間，稽核員三分類時對照 audit 放行。

## 文筆：唯一的指定動作是讀範本

文筆現在是工作範圍，但這一節**不給規則**，因為手藝寫成戒律就會變成規格品（見〈規則的位階〉）。指定動作只有一個：**關 1 動筆前讀 [references/rewrite-sample.md](references/rewrite-sample.md)**，那是同一篇的兩個版本並排，看得出好在哪裡。

三個最常見的毛病，都來自「把訪談當成要交代的對象」而不是「把內容當成要講的事」：

- **導言寫成摘要**：第一段就把論點、代價、主持人身分、後面會吵什麼全部壓進去。張力應該先建立，收攏全文的那句話最後才落下。
- **一段塞三件事**：用「、」「；」把子句串成一大塊。一段講完一件事就換段。
- **但拆過頭一樣糟**：五個平行的短句各自獨佔一段，閱讀節奏每兩句就重啟一次，資訊沒少，文章卻被切成一格一格像筆記。**平行句群要併成一段，用句型平行製造力量**；段落層次是有拆有併，不是只拆。
- **替逐字稿做導讀**：「他在這裡自己先鬆了口」「第二個理由他回頭展開」「他把話收回自己的立場」。判準很簡單：**拿掉「他說／他接著／他回頭／他補充」之後，這句還剩下內容嗎？** 沒有就重寫。單人口播稿特別容易長出這種句子。
- **小標在報告採訪過程**：「主持人不服」「他自己主動回頭說」「年度選書」。同樣的內容，視角換成從故事裡面看就好了。

## 改寫層：預設就是改寫

**預設動作是把原話改寫成第三人稱敘述。** 原話本身帶有額外價值時才留「」。

下面四種是最常見的「值得留」，**不是封閉清單**。看到一句改寫後就會失去某樣東西的話，留著，不必先去對照這四項：

1. **態度比資訊重要**：「結果我當然完全錯了，事情演進的速度比我預期的快太多。」改成「他承認自己低估了進展速度」資訊沒錯，但人不見了。
2. **鮮明的比喻**：「一旦你習慣了快的模型，就很難回去了。有點像寬頻。」
3. **一句話收攏整個立場**，而且前文已經用敘述把機制講清楚，原話只是收尾。**不得拿一句漂亮的話代替機制解釋。**
4. **不確定性或自我限制寫得特別精確**：「我不知道六個月或一年後會怎樣，但現在人的巧思仍然超級重要。」這種句子一改寫就容易掉限定，留原話最安全。

通常該改寫的：技術定義、公司規模、benchmark 數字、流程描述、客戶案例、歷史背景、一長串口語解釋。一段 150 字解釋 memory bound 的原話，成文多半是 2 到 4 句第三人稱。

**沒有佔比指標可以追。** 「連續兩段都以原話為主代表編輯還沒做完」是一條經驗判準，不是禁令：一組精彩的攻防連著引兩段完全可以。`final_gate.py` 只守 0.55 的**上限**（硬性），那是在擋「整篇還是翻譯稿」，不是在管單一段落。

**人物訪談與技術訪談的合理佔比本來就不同。** 講話有味道的人多留幾句原話是對的，不要為了貼近某個數字把人寫沒了。

改寫時仍受引號內那套約束的精神管轄：**保留原意、語氣強度、否定、條件、因果與時間順序**。改寫比引述更容易掉限定，所以掉限定就是錯誤，不是文筆問題。

講者原話一律用「」承載，不用 `>` 引用塊。硬性禁止：虛構引述、把不同講者的話縫成一則引述。

**引述動詞白名單**（硬的，屬於第一種規則）：說、說道、表示、問、追問、回答、回應、反駁、指出、認為、強調、解釋、形容、提到、提出、講、補充。清單以外一律不准，包括「補上」「補一句」「補回」這種只差一個字的變體，也包括「笑著說」「打趣」「話鋒一轉」「補刀」這類舞台指示。

這條之所以硬，是因為報幕詞會替講者加上他沒有的態度，那是歸屬錯誤不是文筆問題。`final_gate.py` 那邊是黑名單、必然漏抓新變體，所以源頭必須用白名單；派工時整份貼進 prompt。

**它只管引出「」的那個動詞。** 第三人稱敘述怎麼寫不受這張表約束，「他排斥的是另一種節奏」「他把終點講得很具體」都合法。唯一延伸過去的是：敘述同樣不得替講者加上他沒表現出來的態度。

## 去冗贅層：什麼可以整段丟掉

訪談天生冗贅。**判準只有一條：拿掉這段之後，讀者是否少知道一件關於世界、技術、公司、人物立場或反方論點的事？** 答案是否就刪。下面是常見的四類，判準優先於清單：

1. **訪談流程句**：「接下來我想問」「你剛剛提到」「這很有趣」「最後一個問題」「這是個好問題」「對，完全同意」。沒有新增命題的附和與鋪陳一律刪。
2. **同一命題的低資訊版本**：A 段的命題被 B 段完全涵蓋，而且 A 沒有額外的數字、限定、例子、反方或態度，A 就刪。
3. **只有情緒、沒有論證功能**：「這真的非常令人興奮」。除非那個態度本身值得保留，否則刪；同一個詞出現五次，最多留一次。
4. **重複證明同一件事的例子**：一個主張有四個例子不必全留。保留的例子要至少滿足一項：唯一的實際案例、帶量化資訊、能解釋抽象概念、構成反例或限制、後文還會用到。

**絕對不能因為「這樣比較順」而刪掉的**：plan (c) 登記的任何一條命題、量化主張（數字不得模糊成「很多」「一部分」）、限定句、主持人提出的獨立反方論證、以及講者承認自己看錯或不知道的話。

**限定句是最容易在重排中死掉的東西**，看到這些詞要提高警覺：不知道、還沒有、可能、目前、至少、下限、在什麼規模下、六個月或一年後不知道。它們是防止文章把講者說得過頭的保險絲。

## 編排層：順序由論證決定，不由訪談時間決定

⚠️ **先讀這一段，這是實測最大的失敗模式。** 2026-09-21 首批四篇，三支 agent 都把命題清單當成**段落鎖**：既然每條都不能丟，那就每段都不要動，結果交出來的只是「拿掉引號的 draft」，第二階段的編輯根本沒有發生。

**命題清單是 coverage constraint，不是段落鎖。** 它只要求每條命題在成品裡**找得到**，完全不要求原本的段落、順序或切分方式被保留。句子可以拆、可以併、可以搬到別節；案例可以重新排序；同一條命題的重複證據可以壓縮成一次。`check_claims.py` 在你編完之後才跑，那是驗收不是寫作限制。

**draft 是有行號保障的素材庫，不是成品。** 真正的工作是重新決定資訊的順序、每一段的功能、哪些合併、哪些壓縮，以及每一段怎麼推動下一段。

幾個從實戰批評裡長出來的判準：

- **不要先摘要答案再展開答案。** 一般性的理論要放在案例**之後**，由案例歸納出來。把「大型組織被聚光燈照到會結陣自保」放在五個案例前面，讀者接著看五個案例時會一直覺得自己看過了；放在後面，同一句話就變成論證得出的結論。
- **同一類材料要用同一套框架走。** 五場災難如果都回答「哪裡壞了／制度怎麼讓它發生／誰進去追／最後改了什麼」，讀到第五個時對比自己就成立了；每個案例各自挑重點講，文章有材料但不會形成 pattern。
- **標題與小標承諾的東西，正文要兌現。** 標題寫「五場災難」，小標就不能只看得到四個。
- **講者的 distinction 不能被標題吃掉。** 他說的是「缺少制度化、多路、資源充足的調查」，標題寫成「只有這件事沒人追」比較抓眼球，但會抹掉他自己強調的區別。
- **重要的自我限定要提前。** 「我刻意不選邊」這種框架句放在倒數第二節，前面十節的強指控讀者已經按另一個框架讀完了。限定先給，後面的材料才知道要放進哪個框架。
- **問答材料要拆回它該去的主題。** 只把 Q&A 往前搬一點，讀起來還是「演講完了接著問答」。媒體為何沒追就併進調查力量那節，陰謀論標籤就併進 manufactured consensus 那節。真正適合留在結尾的，是能收攏全文的那一題。
- **不要讓連續的列舉被打斷。** 講者在數「第一、第二、第三⋯第四」，中間插進主持人問答再回來講第四點，那是逐字稿邏輯。四點一口氣講完，追問放到後面當延伸。
- **重排之後敘事時間要成立。** 把演講結尾搬到問答之後，就要寫成「演講本身在進入問答前，收在⋯」，否則時間倒帶。


先找出一條能回答「這個人到底在主張什麼、為什麼」的主線，整篇依它排列。這條主線比訪談的時間軸重要。

排序通常照這三個順位，但主線長什麼樣是每一篇自己的事，不要套模板：

1. **論證鏈**：背景 → 核心主張 → 機制 → 證據 → 案例 → 反方 → 回應 → 限定 → 預測。這是骨架的一種寫法，不是每篇都要跑完九個環節。
2. **讀者的認知順序**：讀者理解 B 之前必須先知道 A，A 就放前面。不要在讀者還不知道某個產品是什麼的時候，先講它的技術限制。
3. **主題分組**：只有訪談時間相鄰、邏輯上無關的兩件事要拆開放到各自該去的地方。

**同一命題只講一次。** 講者在三個位置講同一件事，合併成一段，錨點掛齊全部出處（`[L200-211][L455-460][L730-738]`）。合併時採用**資訊最完整的版本**，優先序：有限定的 > 有機制解釋的 > 有數字的 > 有具體例子的 > 口號版。

**合併後的確定程度，取所有來源中最保守的那個。** 前面說「X 更省資料」，後面說「文獻有證據，但不知道放大之後是否成立」，合併後必須保留後者的限定。

主張與證據散在不同位置時，搬到一起：原理 → 數據 → 實際案例。

**只有兩種情況保留訪談原順序**：故事本身需要時間順序（技術演進史）；以及一組完整攻防（主持人質疑 → 回答 → 追問 → 再回答）。

## 小標層：小標是結論，不是標籤

小標寫這一節**得到什麼結論**，不是這一節**屬於哪一類**。

不要寫「技術背景」「公司現況」「未來展望」。要寫「兩年後，他估計至少 20% 到 30% 的 workload 對延遲極度敏感」。

判準：**只讀全部小標、不讀正文，能不能大致還原這篇的論證？** 可以，小標才有用。

優先序：有數字的結論 > 有明確因果的結論 > 有衝突的命題 > 有人物立場的判斷 > 普通主題。這是選材順序，不是句型模板；小標照樣可以短、可以只有幾個字。

**小標不能比正文更確定。** 正文寫「他不知道 X 最後會不會成立」，小標不得寫成「X 會成立」。小標要繼承正文的限定。

**切節看論證功能有沒有變，不看字數**：問題換了、證據型態換了（原理 → 客戶案例）、出現真正的反方、時間尺度改變（現在 → 兩年後），任一發生就考慮切。一節裡有 4 到 8 個短段落很常見。**不因為超過幾百字就機械切段。**

## 翻譯層

引號外文字代表編輯者，寫成通順的繁體中文。**以下前三條是正確性問題，寫錯就是錯；其餘一次寫好，不回頭重寫整段。**

必須做到的（這些只有讀得到英文原文的人做得到）：

- **譯文不得改變原意**：否定、條件、方向、時間順序、限定語一個都不能掉。「Rather than scaling with human input」譯成「隨人類輸入擴展」是把否定翻成肯定，這是錯誤不是文筆。
- **具體的東西一律留**：人名、機構名、書名、會議名、比喻、例子。查不到全名時保留字幕能確認的部分，不要因為「無法查證」就整段捨棄。
- **講者沒講完的句子照留**（「他們早就... 」），不要替他補完整。
- 可自然翻譯的普通英文詞翻成中文；專名與術語（router、flops、prefill、decode、neocloud、continual backprop）直接用，不加註解、不加括號說明。

順手做就好的：句序重組、拆句合句、刪掉重複串接、小標少而短只當路標。

## 查證痕跡與認知地位

**查證流程不是正文題材。** 外部來源、口徑差異、歸屬判斷、未採用的說法預設全部進 `_audit.md`。判準：刪掉這句之後，事實與邏輯有沒有改變？沒有就刪。

禁止句式：「這段話的主體是……」「只能證明／不能證明……」「不代表每個案子都會有相同結果」，以及段尾補一句正反平衡。若正文事實本身錯了，直接寫正確事實，不重述錯誤、不解說查證過程。

**但「這是誰的主張」不是查證痕跡，是內容的一部分。** 改寫成第三人稱之後，原話的引號消失了，讀者很容易把「受訪者主張」讀成「已證實的事實」。把認知地位寫回去是必要的，不是囉嗦。

五種情況必須標明歸屬或限定：

1. **預測未來**：用「他認為」「他押注」「如果這個判斷成立」，不要寫成定論。
2. **比較性主張缺細節**：講者說自家產品「品質相當而且更快」，逐字稿沒有 benchmark 名稱與分數，就寫「依他的說法」，必要時補一句訪談中沒有展開具體數字。
3. **市場規模或比例是本人估算**：講者自己說「我做了一些估算」，成文不得寫成客觀數據。
4. **從文獻概括出更大的結論**：原話有兩層限制（文獻有證據、放大後未知），兩層都要寫回去。
5. **公司方談自己的產品**：除非逐字稿提供獨立數據，否則一律當成公司方主張，語法上標明歸屬。

**優先用歸屬語法，而不是編輯註。** 「他認為」就夠了的時候，不要再加一句「訪談中沒有提供證據」。只有當講者提出了一個讀者極可能誤當事實的強斷言、而訪談確實沒給任何根據時，才允許一句中性註記，最短形式，不解說查證過程。

此規則只約束編輯者文字。**講者自己講的限定語、條件、反方、否定照留。**

## 核對要點

**覆蓋**：讀完整逐字稿，不只搜尋關鍵字。**去冗贅之後，覆蓋的單位是命題不是段落**：同一命題講三次寫一次是正確的，一條命題一次都沒寫是漏。判準是：**重要論點、數據、部位或利益揭露、標的名、機制解釋、反方例證不得遺漏；廣告、寒暄、附和、流程句、重複例子可以捨棄，成批捨棄的在 audit 記一筆。** 錨點契約加上 `audit_worklist.py` 的 [B] 區把「逐字稿→文章」這個方向機械化了，但腳本只看行號有沒有被認領，**認領了不等於寫對**，稽核關仍要抽驗。

**覆蓋的三層政策**：內容重要但**講者判不出**時，改用不指名寫法照補，**不得整段丟棄**。判不出是誰說的不是丟掉內容的理由；歸屬的保守只該降級指名，不該降級覆蓋。（實測 2026-08-06 The Compound：producer 以「掛名不確定」為由丟掉全篇唯一的量化反方。）

**段落尾巴被切斷**：長訪談的漏補多半不是整段消失，而是講者講完主論點後那句**自我限定、反向條件或收束**被切掉，只留下前半的強斷言。2026-08-19 那批 44 筆補回幾乎全是這一種。`audit_worklist.py` 的 [C] 區專門偵測它（錨點結束後緊接 but／although／the good news／不過／ただ 這類開頭且該行未被認領），但它是高召回低精準的篩子，**命中要人工判斷，沒命中也不代表沒有**。

**數字**：逐一對帳金額、百分比、倍數、日期、排序、單位與區間，並檢查方向（增加至／增加了、少於／至多、先後／同時）。**英文量級**：million＝百萬、billion＝十億、trillion＝兆；不可把 billion 寫成「億」而少乘十倍。

**數字的 ASR 重建**：只有逐字稿內另有第二來源時才可改數字，並在 plan 與 audit 同列兩個行號。找不到就保守改寫、不填數字；禁止靠單一算式回推。

**專名**：人名、公司、產品、地名、技術名詞全部對逐字稿。只有 ASR 可疑、查無、易混淆的才做外部查證。同音／近音亂詞依上下文重建（`training` 被聽成 `trading`），重建不出就保留原樣並標 `ASR 存疑`，不得美化成另一個猜測。**搜尋結果只證明這個詞存在，不證明講者要說它**（IMEC／in-rack 教訓）。

**歸屬**：只依 plan 的講者地圖指名。沒有被直呼、被介紹或自報的行號，就用角色寫法；`final_gate.py` 對無 plan 證據的英文講者名報 `[硬性]`。

⚠️ **單人影片不是沒有歸屬問題，是換一種。** 要分的是**講者自己的主張／他念出來的文件原文／他轉述第三人的話**這三層，順稿會把三層壓成一層。判準是**主詞與人稱**（"we're swinging" 的 we 不是他）與**引導語**（see for example／they said／播放片段）。`/yt` 對單人頻道也會硬切出「主持人／某某」的假二分，一律回逐字稿確認有沒有第二個聲音，沒有就全篇歸一人。

順稿的說話人標籤是模型猜測，不是證據；一律回原文逐字稿填講者地圖。

## 三關流程

前兩關使用互不共用 context 的 agent，關 3 由 root 自己跑腳本。root 只派工、跑腳本、讀短收據，不讀 `_lines.txt`、`_map.json` 或正文。派工只給路徑、角色與逐條禁止事項，**不預告人名、公司或結論**（那會污染產出）。

### 關 1：規劃＋寫作（同一個 agent，同一份 context）

規劃與寫作合併，逐字稿只讀一次。禁止讀 `_map.json` 全文、禁止把 `_分流稿` 正文當依據、禁止跑 gate、禁止上傳。

先落 `<base>_plan.md`，四塊缺一不可：

**(a) Segments 規劃**：用 `read_triage.py` 拿到 segments 後**逐段**標「寫／精簡寫／不寫」＋理由＋一句話預期寫什麼。扣掉廣告後，寫或精簡寫至少 80%。理由不能用「邊枝」跳過實質內容。

**(b) 講者地圖與拼寫表**：表頭固定如下，供 `final_gate.py` 解析。

| 成品稱呼 | 在場證據 | 行號 | 證據原文 | 英文拼寫來源 |
|---|---|---|---|---|
| 成品實際用名 | `被直呼`／`被介紹`／`自報`／`不可指名` | `L7` | 原文逐字摘錄 | `影片標題`／`description`／`畫面 00:00`／`搜尋 <URL>` |

第三人稱提及不算在場證據。沒有前三種就填「不可指名」，成品改用主持人／另一位主持人／有人。

英文拼法認四種來源：影片標題、description、畫面時間碼（填 `畫面 0:20`），以及**人名專用的**`搜尋 <URL>`。字幕與頻道常識不算來源，查不到就不寫英文。

搜尋這條三條同時成立才可用：**只給人名**（公司名、產品名、benchmark、技術名詞一律不准）、**這個人必須先有在場證據**（不得用來新增一個字幕裡沒有的人）、**只有關 1 與關 2 可以查**。

⚠️ 機械關對這張表很挑，以下寫法會讓正確的 plan 報 `[硬性]`：名字用反引號或雙引號包起來、來源欄夾註、只登全名不登成品實際用的簡稱、**在場證據行本身被 ASR 拼錯**（例：`被直呼 L95 / I'm looking at Kerm now.` 判不成立，因為那行既沒有逗號、名字也被聽成 Kerm；改用 L21 的 `被介紹 / Rich is joined by Kuram Javeed, ...` 才過）。全名與簡稱各列一行。

**(c) 命題清單（不可遺失清單）**：這是重排政策的核心防線。順序一旦重組，漏掉一條主張就再也看不出來。逐條編號，`check_claims.py` 靠編號比對 draft。格式：

| # | 功能 | 講者 | 命題 | 限定 | 行號 |
|---|---|---|---|---|---|
| #7 | 核心主張 | Sergio | 他只在已經懂的領域下注 | 他自己說這是保守 | `L210-218`、`L455-460` |

功能欄用這幾個：`背景`／`核心主張`／`機制`／`證據`／`案例`／`反方`／`回應反方`／`限定`／`預測`／`公司資訊`（不夠用就自己加，這一欄是給人讀的）。主持人的話分成 `主持流程`（可刪）與 `反方`／`主持人補充背景`（不可刪），**分錯這一欄，成文就會把主持人的想法寫成講者的想法**。

同一命題在多處出現就在行號欄列齊，不要拆成多條。反方與被反駁的主張各自編號，並在限定欄註明它在回應哪一條，避免接反。

**(d) 數字／專名／ASR 疑點**：逐筆附行號；ASR 數字修正同列第一來源、第二來源與處置。沒有第二來源就保守改寫。

接著寫 `<base>_draft.md`（**帶行號錨點與命題編號**，見〈行號錨點契約〉）與 audit 第 1、2 節，完成後立即停。**不自審、不重寫、不湊字數。**

**手藝規則可以偏離，在 audit 第 1 節寫一行理由即可**（例：這位講者的話有味道，原話比舊政策多留了幾句）。不要為了滿足某條判準把句子扭成規格品。

寫作順序固定：**先排主線，再寫段落。** 不要打開逐字稿就從第一行開始順著潤。照〈編排層〉先決定這篇的論證鏈長什麼樣、哪幾條命題要合併、哪幾段整段不要，再動筆。照訪談順序寫完再回頭重排，等於做兩次，而且第二次會捨不得刪。

分次落檔：長稿不要一次 Write 整份，分 3 次以上寫，避免長輸出斷線。

### 關 1.5：機械待查清單（root 跑，不派 agent）

```bash
.venv/bin/python .claude/skills/humanizer-zh/scripts/audit_worklist.py \
  <base>_draft.md <base>_lines.txt
.venv/bin/python .claude/skills/humanizer-zh/scripts/check_claims.py \
  <base>_draft.md <base>_plan.md
```

- `audit_worklist.py` exit 1 = 錨點不可信（沒錨點／認領率 <50%／有超寬錨點／範圍無效）→ 退回關 1 補錨點，不進稽核。
- `check_claims.py` exit 1 = plan (c) 有命題完全沒被認領 → 退回關 1。**重排政策下這是最貴的錯誤**：不是寫錯，是整條主張消失，而通讀成品看不出來。
- **認領率的門檻在新政策下要重讀。** 去冗贅會讓認領率天然下降（附和、流程句、重複段落本來就不該認領），80% 以下不再自動代表漏段。改看 [B] 區每一處的性質，以及命題清單有沒有清零。
- exit 0 = 把 [B][C][D] 三區的清單**原樣貼進關 2 的派工 prompt**。這是稽核員的待查表。

⚠️ **中文來源與長行來源，這張表大部分失效**（2026-08-22 硅谷101 實測：102 行、平均每行 191 字元）。[D] 用中英字數比，中文來源量不出來，腳本會明寫「不適用」；[C] 靠行邊界找轉折句，一行就是一整段時對不準；認領率 99% 也只是因為總共才 102 行。**腳本印「無命中」不等於「查過沒問題」**，這種集數的覆蓋只能靠關 2 逐行比對，派工時要明講。

### 關 2：盲審

使用未參與關 1 的新 agent。**閱讀順序硬性規定**：先讀 `_draft.md`，再讀完整 `_lines.txt`，需要時查 `_plan.md`，**最後才讀 audit**（先讀 audit 會被關 1 的結論錨定）。直接改 `_draft.md`（錨點跟著改），完成 audit 第 3 節。

**只查八件事**（前五件是舊政策就有的，後三件是重排政策新增的，也是新政策最大的風險所在）：

1. **歸屬**：每則引述回逐字稿確認說話人；plan 標「不可指名」的不得指名；不要把只有一個聲音講的話掛成兩個人。
2. **數字**：逐筆對帳與方向；量級換算。
3. **捏造**：逐字稿查無的事實、數字、因果、立場、評價一律刪，整段查無就整段刪；特別查憑常識補出的機構名、benchmark、產品名、書名、人名、年份。
4. **待查清單**：[B] 未認領區間逐處判「該補／可捨棄（audit 記一筆）」；[C] 疑似斷尾逐處回逐字稿看那句限定有沒有被切掉；[D] 疑似壓縮逐處確認引述有沒有掉半截。清單只是篩子，**沒被標到的地方仍要抽驗**。
5. **譯文有沒有改變原意**：否定、條件、方向、時間順序、限定語。
6. **每一句第三人稱敘述，逐句問「這句由錨點那幾行直接推出嗎」**。原話改寫成敘述之後，超譯不再有引號保護，這是新政策唯一的破口。特別查自補的因果：逐字稿只說了 A 然後 B，成文寫成「因為 A 所以 B」就是捏造因果，改成接著／同時／在這個背景下。`final_gate.py` 會把「因此、所以、導致、促使、使得、證明、顯然、勢必」報成 `[候選]` 供你定位，但它只是篩子。
7. **全篇內部一致**：同一個東西在不同段落的稱呼有沒有打架（實測：同一個組織前面寫「做病毒學研究的非營利組織」、後面寫「某某人的公司」）。這不需要外部查證，稿內比對就找得到。標題與小標承諾的東西，正文有沒有兌現。
8. **限定與歸屬有沒有在重排中死掉**：合併版本時有沒有掉掉最保守的那個限定；小標有沒有寫得比正文更確定；講者的估算、預測、公司自我宣稱有沒有被寫成客觀事實（見〈查證痕跡與認知地位〉五種情況）。

**順序硬性：八項先做完，再談文筆。** 八項沒做完就去修句子，是這條流程歷史上最常見的浪費：不會硬失敗的規則在大掃描裡一定會被擠掉。

八項做完之後，**讀起來卡的地方你可以直接改**，這是你的裁量範圍：贅詞、繞口的句序、重複的連接詞、小標不精準。條件有兩個：**不改動語意**，以及**不自行重排整篇結構**（編排是關 1 的職責，位置有問題就在 audit 寫一行，不要搬）。

**明令禁止**：先讀 audit、跑 gate、上傳。

### 關 3：機械驗收（root 跑，不派 agent，不讀正文）

```bash
# 1. 待查清單與命題認領複跑
audit_worklist.py <base>_draft.md <base>_lines.txt
check_claims.py <base>_draft.md <base>_plan.md

# 2. 剝錨點產生交付檔
strip_anchors.py <base>_draft.md          # → <base>_humanized.md

# 3. 硬性門檻
final_gate.py <base>_humanized.md
```

**通過條件：`final_gate.py` 零 `[硬性]`，且 `check_claims.py` exit 0。**

- `[候選]` 全部忽略，不派回合處理。2026-08-19 那批為了三分類候選多跑了兩輪 resume，每輪重餵 150k context，結論全是「這是講者原話所以不動」。
- `check_user_coverage.py` 降為**參考數字**，不再當關卡。它用英文字數回推時長，對快嘴頻道與中文來源都會失真；覆蓋改由錨點與 `audit_worklist.py` 把關，那才是直接量測。想看數字就跑，exit code 不影響交付。
- **機械關誤判自己修，不要退回 agent。** 已知形態：audit 裡「ASR ⋯重建」被當成數字修正缺第二來源（改寫成「疑點」「無從還原」即可）；公司名後面接冒號引號或接到「說成」被當成講者名（拉開距離或換詞）；小標以英文詞結尾＋下一行英文開頭被當成假講者名。改 plan／audit 措辭或換一個詞就好，**正文語意不動**。
- 真正的硬性（歸屬無證據、捏造、數字缺第二來源）退回關 2，最多兩次；第三次停該篇，不硬推。

## Audit 契約

每篇需有同名 `_audit.md`，章節標題固定 `## 1.` `## 2.` `## 3.`。Audit 是給使用者看的證據，不是自證儀式：記錄實際判斷與依據，不寫「已確認」「看起來正確」這類無來源自評，不留 `TODO`、待盲審等未完成字樣。

```
## 1. 改了什麼
重要修正逐條，附逐字稿行號。涵蓋漏補、意思錯、數字、專名、歸屬。純格式修整合併成一條。

## 2. 查過但沒寫進正文的
外部查證結果、口徑差異、未採用的說法、ASR 存疑、未能查證而保留原樣的專名。

## 3. 覆蓋與遺留
開頭一行掃描範圍與筆數（例：「逐字稿 642 行讀畢；待查清單 3+5+2 處逐處三分類，8 處改動」）。
接著：逐字稿有但成品捨棄的內容（附理由，未認領區間的放行理由寫在這）、必改項與處理結果。
```

⚠️ 措辭避開機械關的已知誤判：不要在同一行同時出現「ASR／數字」與「重建／修正／改為」卻只附一個行號。

## 輸入路由

**`_yt_` 檔案先看 frontmatter `type:`：**

| `type:` | 長相 | 怎麼做 |
|---|---|---|
| `yt_transcript_zh` | 中文全文順稿，說話人前綴行，無小標 | 照三關流程走；`_transcript.txt` 是 ground truth |
| `yt_triage` | 中文分流稿，小標帶 `（L120-L180）` 行號，frontmatter 有 `map:` 與 `transcript_lines:` | **分流稿只是閱讀稿，不是底稿也不准編輯**；依據是 `_lines.txt` 的原文，中文全部由你產生。先跑 `read_triage.py`，再讀 [references/yt-triage-map.md](references/yt-triage-map.md) |
| `yt_article` | 已成文、有 `##` 章節，舊版存量 | **有草稿要保護**，是唯一例外：不重排章節、不重寫措辭，只做核對要點那幾項。錨點契約對它不適用 |

地圖版與順稿版**同一批裡會混著出現**，逐檔判型。

地圖版的檔名 base **不含 `_分流稿` 尾綴**（也不含使用者手動加的 `V` 挑片標記）。`final_gate.py` 靠 base 對檔，缺 transcript／plan／audit 一律 `[硬性]`；`read_triage.py` 會印出正確檔名。

其餘輸入：

- **本機 `_yt_` 路徑**：視同完整 production 工作，不因輸入是路徑而降級。
- **批次監督模式**（多個路徑＋要求派 agent）：見下節。
- **`_fb_` 或作者自寫文**：可積極恢復個性、節奏與觀點，但不新增事實；讀 self-authored-voice 與 ai-writing-patterns。這條路徑沒有逐字稿，所以〈編排層〉與命題清單不適用。
- **純文字或其他檔案**：先確認來源與輸出位置；貼文直接回傳改寫文字，檔案預設另存新檔。沒有來源就不假裝核對。

## 批次監督模式

觸發條件：使用者貼多個路徑並要求派 subagent。**使用者不需要再交代分工、context 上限或回報格式，全部照本節執行。**

**root 只做四件事**：派工、跑腳本、驗收收據、回報。不親自改稿（機械關誤判的措辭修正除外）。

- 不讀 `_lines.txt`／`_map.json`／`_draft.md` 的內容；只讀腳本輸出與 grep 結果。root 的 context 爆掉一定是因為讀了正文或收下長篇回報。
- 派工 prompt 只給「路徑＋角色＋禁止事項」。**不得轉述本技能內容**（subagent 自己載入），**不得塞入任何 root 以為的事實**（人名、公司、結論）。
- 一次最多 3 篇並行；同一篇嚴格照關序。

| 關 | 誰做 | 只讀 | 產出 | 明令禁止 | 收據上限 |
|---|---|---|---|---|---|
| 1 寫作員 | agent | `_lines.txt`、`read_triage.py` 摘要、`_meta.txt`、rewrite-sample（動筆前必讀） | `_plan.md`（(c) 為編號命題清單）＋`_draft.md`（帶錨點與命題編號）＋audit 1、2 節 | 讀 `_map.json` 全文；照訪談順序順著潤；自審重寫；跑 gate；上傳 | 12 行 |
| 1.5 清單 | root | — | `audit_worklist.py`＋`check_claims.py`，待查清單貼進關 2 派工 | — | — |
| 2 盲審員 | 新 agent | `_draft.md` → `_lines.txt` → `_plan.md` → 最後 audit | 改 `_draft.md`＋audit 3 節 | 先讀 audit；文筆工作；自行重排結構；跑 gate；上傳 | 15 行 |
| 3 機械關 | root | 腳本輸出 | `_humanized.md` | 派 agent | — |

只寫「你只做關 1」沒有用，模型會順手往下做；**禁止欄必須逐條寫進派工 prompt**。

**收據格式**：結構化短行，不得貼文章內容、不得寫感想。任一 agent 超出行數、開始貼正文、或想跨關做下一步 → root 立刻中止並重派。

**批次回報**：一張表（檔名／segments／認領率／待查處數／硬性／狀態），不複述內容。

## 輸出與發布

原稿保留不動。同目錄同 base：`_plan.md`、`_draft.md`（帶錨點，保留當證據）、`_humanized.md`（交付檔，腳本產生）、`_audit.md`。交付檔正文不得混入 audit、流程說明、分數或「以下是修改後版本」等聊天語句。

```bash
/Users/slking/Documents/訪談摘要/.venv/bin/python \
  .claude/skills/humanizer-zh/scripts/final_gate.py \
  /absolute/path/to/article_humanized.md
```

`final_gate.py` 會硬擋缺 transcript、plan、audit、無在場證據的英文講者名、非法拼寫來源、audit 自證詞、只附單一行號的 ASR 數字修正，以及引號內 CJK 佔比**超過** 0.55（超過代表還是翻譯稿，重排與去冗贅沒做）。**門檻不要改。**

`scripts/upload_hackmd.py` 僅在以下全部成立時執行：三個檔齊全、必改項已處理、final gate 零 `[硬性]`、使用者沒有禁止上傳或要求 dry run。依檔名傳 tag：`_yt_` → `YT訪談摘錄`、`_fb_` → `FB文章`、`_invest_` 或 `_epub_` → `投資筆記`。預設個人空間、`readPermission=guest`。要求原位更新時更新既有筆記，不建立重複筆記。不得輸出 token 或 `.env` 內容。`_yt_` 保留頁尾「本文根據 YouTube 影片內容由 AI 整理生成，僅供參考。」

**`_yt_` 上傳到 HackMD 的不是 `_humanized.md` 全文，是上傳包（2026-09-26 使用者定案）。** 用 `scripts/hackmd_packet.py <base> <精簡說明欄檔> --upload`（原位更新加 `--note-id <id>`）。上傳包＝成品開頭（frontmatter＋H1＋原始影片行）＋給下游編輯的固定指令＋精簡說明欄＋plan (c) 整節＋`_draft.md` 全文（剝掉 draft 自己的 frontmatter／H1，保留行號錨點）。說明欄由 root 手挑：留內容簡介、章節時間碼、持股／利益揭露與來源訪談連結，刪業配、付費推廣、社群連結、求訂閱、免責聲明、hashtag，保持原文不翻譯。指令模板在腳本內，一字不改（含單人口播那句括號）。`_humanized.md` 照舊產生並過 final gate，腳本上傳前會再驗一次。

## 交付回報

回報可驗證事實，不自評分數也不評語感：產出檔案路徑、錨點認領率、命題清單條數與認領結果、待查清單三區的處數與處理結果、引述佔比、重要修正（漏補／歸屬／數字／專名／譯意／自補因果）、final gate 結果、HackMD URL（未上傳則明說）。
